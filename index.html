Accounts & publishing roadmap

Current version

Single-browser prototype. No sign-in, shared database, server, or Discord connection is active.

Phase 2 · User accounts

Supabase Auth (email/password or magic link), unique user IDs, private profiles and secure sessions.

Phase 2 · Cloud storage

Supabase Postgres with row-level security: users can only access their own shapes, cards and items. Optional private screenshot storage with deletion and retention controls.

Phase 3 · Discord

Server-side endpoint or Edge Function sends cards to Discord. Never embed a Discord webhook or secret API key in the public webpage.

Phase 3 · OCR upgrade

Optional server-side vision API for better item extraction, with user consent, usage quotas, rate limiting and cost controls.

Phase 4 · Second Life HUD

Secure LSL-to-backend submission with signed requests and per-user linking; combine attachment scan with screenshot-based BOM recognition.

Before public launch: privacy policy, deletion/export controls, abuse protection, HTTPS hosting, billing limits and a proper authentication backend are required.

Account · log in with Second Life

Log in to keep your own stores online, in every browser. No password or e-mail: 1) In the Studio Landmarks HUD click 🔄 SYNC → 🔑 WEB LOGIN. 2) Type the 6-letter code here.

Stores you send with 🔄 SYNC → 🔄 SYNC ALL in the HUD are used on your styling cards automatically.

Card texts

Used by the card style “Shape & Styling Notes”. Write {BRAND} or {SHAPE} and they are filled in for you. Saved in this browser. Leave a box empty to skip that part.

My brands & stores

Brands that make one kind of product, and their store SLURL. Shared brands come from brands.json; your changes are saved only in this browser. Store links appear right under each product on the styling card.
